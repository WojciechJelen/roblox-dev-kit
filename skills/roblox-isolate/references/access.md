# Access checks for each worker

Isolation separates working state. It does not create Roblox permissions, log into Studio, copy
ignored dependencies, or grant a harness access to tools. Verify the resources needed by the
assigned task in its actual environment before spending time on model changes.

## Local files and tools

- Verify the intended commit, saved map and matching generated asset mappings. Git worktrees get
  committed files only. Dirty tracked files, untracked assets and ignored outputs do not follow
  automatically. Checkpoint the intended baseline or explicitly choose committed state; do not
  run a worker against old asset IDs while comparing it with uncommitted models.
- Restore Wally packages in the worktree with `wally install`, or explicitly seed them with
  `create --copy ServerPackages` / `--copy Packages` when those folders exist. Restore/copy ignored
  type definitions and regenerate the Rojo sourcemap as required by the project. Confirm every
  required `$path` and imported Python module exists.
- Inspect Blender's linked libraries, images, fonts and other external inputs. Pack them or copy
  and relink them into the environment. Render a baseline through the private headless runner to
  prove the inputs and Blender binary work before making changes.
- Confirm each worker has the needed filesystem, command and Studio MCP tools, network access and
  its assigned Studio ID. Separate worktrees do not imply separate tool connections or automatic
  trust in a new project folder. Run the sibling doctor's relevant checks if available.

## Roblox content

- Confirm the Studio instance is signed into the intended creator/collaborator account. A new
  Studio process can pause at login even while its worktree and Rojo server are ready.
- Read the asset mapping used by the worktree and enumerate the task's required models, meshes,
  textures, audio and animation clips. Roblox asset permissions and moderation still apply.
  Access through an Open Cloud API key is separate from access by Studio or a running experience.
- Record the actual place/universe IDs in Edit and play mode. A local place copy can have a
  different context from the published experience. The isolation helper drops cloud ID settings
  from its generated Rojo project; do not assume the local copy inherits experience-scoped grants.
  If it cannot use required restricted assets, resolve the account/context or use an explicitly
  authorized private test experience with the needed grants. Do not make assets public, change
  production permissions or publish a place merely to bypass a failed check.
- Exercise the same load path as the game: for models, load/clone them through its asset service
  and verify expected MeshParts; for animations, load and exercise the required clips. Inspect
  both server and client console output and the rendered result. A graybox/fallback model is a
  failed asset check even when the game keeps running.
- For supported images, sounds and other content, use `ContentProvider:PreloadAsync` with its
  callback to record final fetch statuses. It can return normally even when assets fail, so a
  successful `pcall` alone proves nothing. SurfaceAppearance/MaterialVariant are not supported by
  that preload method: verify their actual runtime rendering as well. Split probes into bounded
  batches and yield; check the task's dependencies rather than indiscriminately preloading the
  entire world. Relevant assets must finish loading before baseline screenshots are accepted.
- `rbxasset://` paths generated by a local Asphalt sync resolve from the machine's shared Studio
  content directory. They are not copied by Git and are not isolated per Studio. Coordinate those
  writes or use separate asset paths. `rbxassetid://` references require the appropriate Roblox
  permissions; changing the URI form is not a permissions fix.

## Credentials and external services

Use the project's credential wrapper from the worker's cwd. On the same OS account, a wrapper
reading a private file outside the repo can load credentials for each child command without
copying secrets into worktrees. A separate machine/user/container needs its own authorized secret
provisioning. Do not print keys, add them to manifests, put them in command-line arguments or
commit them.

Check only the operations the task needs. Credential presence is not proof of API permissions:
use a read-only request to the relevant service where supported. Do not perform a test upload or
publish unless that action is authorized. Give assets the intended creator identity and coordinate
shared asset updates; local environment isolation does not isolate the cloud account. Keep
production persistence/API access out of an art review unless the task requires it.

## Evidence and readiness

Write an `access-check.json` in the environment directory with its environment/Studio IDs, checked
time, baseline commit, and per-check `pass`, `fail` or `not-required` results. Include the dependency
paths, asset IDs, load/fetch results and review-image paths needed to reproduce the check, plus any
unverified limitations. Never include secrets. This report is agent-supplied evidence, not a helper
command that grants or automatically proves access.

Only report an environment ready for the assigned task when its required checks pass. Recheck
after changing the account, place context, asset mappings, dependencies or credential scope.
