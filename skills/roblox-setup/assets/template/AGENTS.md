# {{PROJECT_NAME}}: instructions for coding agents

A Roblox experience written in strict Luau, synced into Studio with Rojo. Code lives in git; the map, meshes and other place content live in the place file in Studio.

## Source of truth

- **Files in `src/` are the source of truth for code.** Rojo copies them into Studio. Script edits made inside Studio are overwritten by the next sync, so make every code change in the files.
- `default.project.json` maps folders to the DataModel:

  | Folder | In Studio |
  |---|---|
  | `src/ServerScriptService/` | `ServerScriptService` |
  | `src/StarterPlayerScripts/` | `StarterPlayer.StarterPlayerScripts` |
  | `src/ReplicatedStorage/Shared/` | `ReplicatedStorage.Shared` |
  | `Packages/` (Wally, shared) | `ReplicatedStorage.Packages` |
  | `ServerPackages/` (Wally, server) | `ServerScriptService.ServerPackages` |

- File names decide the instance class: `*.server.luau` → Script, `*.client.luau` → LocalScript, any other `*.luau` → ModuleScript, `init.luau` → the folder itself becomes that script.

## Dev loop

1. `rokit install` (once per clone, and whenever `rokit.toml` changes), then `wally install` if `wally.toml` has dependencies.
2. `rojo serve`, then connect from the Rojo plugin in Studio.
3. Keep `rojo sourcemap default.project.json -o sourcemap.json --watch` running (or let the VS Code luau-lsp extension do it) so types resolve `game.ReplicatedStorage.Shared.*`.
4. Play-test in Studio. With the Roblox Studio MCP server connected, an agent can start and stop play mode, read the console and inspect instances.

## Code rules

- Every file starts with `--!strict`. Fix type errors instead of silencing them; use `:: any` only at a real dynamic boundary, with a comment saying why.
- Server code is split into **services** (`src/ServerScriptService/Services/*.luau`), client code into **controllers** (`src/StarterPlayerScripts/Controllers/*.luau`). Each is a module table with optional `init()` and `start()`. The entry scripts call every `init()` first (no yielding, no calls into other modules' state), then every `start()` in its own thread.
- Shared, side-effect-free code goes in `src/ReplicatedStorage/Shared/`.
- Never trust the client: validate every remote's arguments on the server (types, ranges, rate, ownership).
- Get services with `game:GetService`. On the client, reach replicated instances with `WaitForChild`.

## Checks (CI runs the same)

```sh
stylua --check src      # format: run `stylua src` to fix
selene src              # lint
rojo sourcemap default.project.json -o sourcemap.json
luau-lsp analyze --platform=roblox --sourcemap=sourcemap.json --definitions=@roblox=globalTypes.d.luau src
rojo build default.project.json -o build.rbxl
```

`globalTypes.d.luau` comes from https://raw.githubusercontent.com/JohnnyMorganz/luau-lsp/main/scripts/globalTypes.d.luau and is git-ignored. Run the checks before declaring a change done.

## Blender (when the Blender MCP server is connected)

- Inspect before editing: summarize the scene and the objects involved before running any code.
- Put reusable operations in `.py` files in the repo and run them, rather than pasting long one-off snippets.
- Make scripts idempotent: look objects up by name and update them; never create duplicates on a re-run.
- Save a checkpoint copy of the `.blend` before large or destructive changes.
- Render a preview (thumbnail or viewport render) and look at it before declaring visual work done.
- One writer per open scene: do not edit the same scene from two agents or from an agent and a person at once.
- Roblox limits: about 20k triangles per mesh, 1024×1024 textures, 1 stud ≈ 0.28 m. Prefer simple collision (`Box` or `Hull`).

The Blender MCP server runs Python generated by the model inside Blender without a sandbox. Only connect it to scenes you have backed up.
